# v5 时机实验：执行条件收紧后是否必须更早知道（冻结策略，只改变视觉时机与 jerk 上限）

日期：2026-09-14。脚本 `visual_dev/v5_timing_experiment.py`，结果 `runs/v5_timing/`（每分支一个 JSON，含逐子步与逐决策记录；配置哈希命名，已完成自动跳过）。

## 1. 唯一要回答的问题

同一条视觉线索，较宽松的执行条件（jerk 上限 4 m/s³）允许晚一点知道；执行条件收紧（2 m/s³）后，是否必须更早知道，才能保住平顺停车的机会？不验证联合编码器、不新增网络、不重训。jerk=4 是机制对照条件，不是建议采用的舒适性标准。

## 2. 设计

| 因素 | 设置 |
|---|---|
| 策略 | v4r 三个仅监督 S 权重（`runs/v4r*/v4_pilot/supervised/final_nets.pt`），检测器、编码器、actor、记忆规则全部冻结 |
| 信号情境 | 需要停车（名义到达时刻处于红灯中段，剩余红灯约 30 s）/ 允许通行（名义到达时绿灯早段，剩余约 25 s），通过外部信号相位偏移设定 |
| 执行条件 | jerk 上限 2 / 4 m/s³，同时改 `curve_layer.J`、`curve_layer.Q=J·DT`、`env20.J_MAX`（备份制动/可行区间、投影裁剪、越界计数三处统一） |
| 视觉条件 | 正常可见（灯进入 200 m 可见区即出现）/ 中等延迟 / 较晚可见：指定位置前整个信号灯（灯箱、停止线、标签、ROI）不在图像里，之后恢复正常画面；检测与编码两条图像路径同时不可见 |
| 起始条件 | 一组预先冻结的车辆状态（灯尚不可见处） |
| 规模 | 3×2×2×3 = 36 条短程分支（冻结点 → 停止线后 300 m 或 150 s） |

**冻结状态**（用 S 种子 0 权重从开发工况 0 行驶到 x ≥ 2740 m 处冻结）：t = 136.0 s，x = 2746.8 m（停止线 3000 m，灯从 2800 m 起可见），v = 22.22 m/s，a = 0.00，SoC = 0.837；记忆中无灯轨迹（弯道已解除、终点未见），含最近 4 帧图像历史、相机外观与噪声随机流状态。所有 36 条分支从同一份完整状态深拷贝出发（视觉记忆、投票状态、图像历史、随机数状态），同一情境的配对分支外观流与外部信号时序相同，轨迹分开后相机按各自位置重新渲染。

**评价接口**（不用旧 critic）：保持 2 s 的命令 → 4 个子步的实际执行 → 状态变化与累计代价。每个决策记录命令、4 个子步的实际加速度、实际 jerk、起止状态（t, x, v, a, SoC, 电池能量）、Δv/Δx/ΔE 与回报；每个子步记录真值相位、隐藏标志、检测分数与灯色、记忆相位与距离估计、执行目标、回退/越界标志。

**四个时刻**：线索开放（灯首次可被渲染）、检测器首次正确识别（分数 ≥ 0.4 且灯色 = 真值）、正确信息首次被记忆采纳（记忆相位 = 真值）、执行动作首次因此改变（采纳后首个有灯目标且执行层干预的子步）。**停车余量** M_j(t) = d_line(t) − D_stop,j(v_t, a_t)，D_stop,j 为 `curve_layer.backup_distance` 在 jerk 上限 j 下的备份制动停车距离（当前离散动力学下该备份的距离；负余量只说明该备份失效，不是所声明控制类中的不可行——本轮未做约束优化核对）。

## 3. 延迟位置的选择（物理余量，烟测后冻结）

冻结速度 v = 22.22 m/s、a = 0：D_stop,2 = 84.9 m，D_stop,4 = 75.4 m，窗口 D_2 − D_4 = 9.5 m（≈ 0.43 s）。执行层停车目标在线前 0.15d+8 m，故 jerk 上限 j 下“采纳时仍能按备份平顺停到目标点”的条件是 d_adopt ≥ (D_j + 8)/0.85：jerk 2 需 ≥ 109.3 m，jerk 4 需 ≥ 98.1 m。

- 中等延迟：采纳时 M2 恰为执行层余量（jerk 2 的备份恰能停到目标点）→ d_adopt = 109.3 m；
- 较晚延迟：采纳时 M2 < 0 而 M4 ≥ 0 的中点 → d_adopt = (D_2 + D_4)/2 = 80.1 m；
- 采纳延迟 τ（线索开放 → 记忆采纳）：第一次烟测假定 1.5 s，实测 0.5 s（首帧检出、次帧投票建轨），按实测更新一次后冻结：灯出现距离 中等 120.4 m（x = 2879.6）、较晚 91.2 m（x = 2908.8）。

烟测（S 种子 0，12 条）在冻结延迟前看过一次结果，因此种子 0 的正式行标为开发证据；种子 1、2 未参与选择。

## 4. 接口核对（全部通过）

1. 同一分支两次运行逐子步（t, x, v, applied, 检测分数, 记忆相位）完全一致（120 子步）。
2. 隐藏期 14 个子步灯检出分数最大 0.033（阈值 0.4），记忆无灯轨迹——两条图像路径都没有提前得到灯色。
3. jerk 参数生效：非回退子步 max|jerk| = 2.00（上限 2）/ 4.00（上限 4）；应急回退子步不受 jerk 上限约束（设计如此，计入越界）。
4. 冻结包内容：4 帧图像历史、记忆快照（无灯轨迹）、相机噪声流 `numpy.Generator` 状态、外观参数。

**读法**：
- 正常可见（采纳时 d = 187 m）：两种 jerk 上限、三个权重的高速段全部平顺。
- 中等延迟（采纳时 d = 109 m，M2 = +24…+30，M4 = +33…+36）：jerk 2 在采纳信息后的第一个决策（d = 98 m，v = 21.5 m/s）就进入应急制动（3/3 权重），jerk 4 三个权重全部保持平顺——较严格的执行条件已经失去平顺停车余量，较宽松的仍能完成。
- 较晚可见（采纳时 d = 75 m，M2 = −9，M4 = 0）：两种条件都在 d = 65 m、v = 20.5 m/s 处应急（3/3 权重），更晚的识别进一步恶化。
- 全部 36 条分支都到达终点、0 信号违规；需停车分支能耗随延迟递增（约 92 → 121 → 132 Wh），时间由等红灯主导（约 60 s）。允许通行分支在中等/较晚延迟下按“首见即绿假定剩余 30 s”直接通过（I_j ≈ 0），该假设照旧披露。

**重复性**：三个权重在中等与较晚延迟下的时刻记录与首次回退位置逐值相同——因为冻结状态相同、灯出现后执行层主导（v4r 执行层干预 88–95% 子步），策略命令的差异只体现在灯出现前的巡航段和起步段。这既是重复支持，也说明本实验度量的是“执行约束 × 信息时机”的机制，不是策略差异。

## 7. 这组结果支持什么、不支持什么

支持：在实际视觉链路（同一冻结检测器、记忆与执行层）里，执行条件收紧后，同一条视觉线索必须更早被采纳才能保住平顺停车机会；差异发生在响应机会消失之前或附近（首次应急回退紧随采纳时刻），实际执行结果与余量 M_j 的符号变化对应，在三个冻结权重上重复，且没有隐藏信息（隐藏期无检出）、参数未同步（三处 jerk 参数统一）或记忆初始化差异（同一冻结包）造成。固定策略下的行程差记为该策略下的配对效果。

不支持 / 局限：(1) 差异窗口只有一帧（0.5 s / 11 m），由 D_2 − D_4 = 9.5 m 与 2 Hz 感知决定，更细的分辨需要更高帧率或更大的 jerk 差；(2) M_j 为备份制动口径，负余量不等于控制类内不可行；(3) 执行层主导使三权重结果相同，本实验不能说明策略学到的准备行为；(4) 允许通行情境没有出现两难区（首见即绿假定 30 s），因为通行分支到达时绿灯剩余充足；(5) 通行/jerk 4/正常/种子 1 分支在过线处出现一次 jerk 10.4 的应急（记忆灯色近线抖动导致的短暂停车目标），属 v4r 已知近线感知问题，如实计入；(6) 终末低速修正的回退（jerk 2 下 3–10 子步）来自执行层停车目标随距离收敛，属执行层设计，与信息时机无关。
